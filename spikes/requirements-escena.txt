# Dependencias de `.venv-escena`: el obrero de activos del motor de escena (F6.2c, Loop 6).
#
# Qué corre aquí: `lib/escena/obrero_worker.py`, que amplía ×4 con Real-ESRGAN (spandrel), recorta con
# SAM 2.1 (transformers) y deja cada figura lista para el catálogo. OpenCV y scikit-image van para la
# geometría y el color de las piezas de un canal (la bici por piezas, el pelaje que Qwen aclaró), que
# llegan con F6.3. El resto del pipeline sigue en `.venv`; este venv no lo usa nadie más.
#
# Por qué un venv propio y no el de ComfyUI: en video_1 estas herramientas corrieron dentro de
# el `.venv` de ComfyUI (`<COMFY_ROOT>\.venv`), que puede ser compartido con otros proyectos. El estudio no
# instala nada ahí (plan de F6.2, regla 4). Del ComfyUI solo se LEE el peso de Real-ESRGAN
# (`lib/config.py → ESCENA_ESRGAN_PESO`); SAM 2.1 sale de la caché de Hugging Face.
#
# Python: 3.12, el mismo de los otros entornos, para que quien instala Lanternist necesite uno solo (OC1.7). Se creó
# el 29-09-2026 con 3.14.4, el del sistema; el 24-10-2026 se comprobó con `pip install --dry-run --python-version 3.12
# --only-binary=:all:` que todo tiene rueda para 3.12, y la prueba de humo de OC1.7 lo creó así y produjo con él
# (`progress/impl_OC1.7.md`).
#
# Lo crea `py -3.12 instala.py` (paso entornos). A mano son TRES pasos, y el orden importa:
#
#     py -3.12 -m venv .venv-escena
#     .venv-escena\Scripts\python -m pip install torch==2.13.0+cu130 torchvision==0.28.0+cu130 --index-url https://download.pytorch.org/whl/cu130
#     $env:PYTHONUTF8=1; .venv-escena\Scripts\python -m pip install -r spikes\requirements-escena.txt
#
# (`PYTHONUTF8=1` es por TrustMark, más abajo; `instala.py` ya lo pone.)
#
# **La trampa, medida al crearlo**: spandrel depende de torchvision, y si torch y torchvision no se
# instalan ANTES desde el índice de CUDA, pip trae de PyPI `torch 2.14.0+cpu` y desinstala el de CUDA
# sin avisar. El obrero lo cazaría (exige `torch.cuda.is_available()`), pero es una hora perdida.
# torch 2.13.0+cu130 es la misma versión que usa el ComfyUI de la máquina con esta tarjeta y este
# controlador: la combinación ya probada.
#
# **La marca de IA (OC1.5, filas 309, 311 y 312) también corre aquí**: `lib/marca_ia_worker.py` marca la imagen del
# vídeo y la miniatura con Video Seal (un TorchScript que solo pide torch), el audio con AudioSeal, y firma con C2PA
# (c2pa-python, que trae cryptography). PyAV decodifica el vídeo dentro del proceso: leer 1080p por una tubería de
# ffmpeg desde Python es cinco veces más lento en Windows. AudioSeal 0.2 compila su modelo con `torch.compile`, que en
# Windows pide Triton: el trabajador pone `NO_TORCH_COMPILE=1` antes de importarlo. Instalados el 15-10-2026 con el
# permiso del dueño (fila 311), con `pip check` sin roturas. La wheel de PyAV para Windows trae FFmpeg con x264 y x265,
# que son GPL: se instala desde PyPI y Lanternist no la redistribuye (`THIRD_PARTY_NOTICES.md`).
#
# **La señal de la marca de IA (OC1.12) es TrustMark 0.9.2** (Adobe, MIT el código y los pesos): una marca de agua más
# en la imagen, que dice qué detector usar. Solo publica el código fuente, y su `setup.py` lee un texto sin decir su
# codificación, así que en un Windows en cp1252 no se construye sin `PYTHONUTF8=1`. Arrastra Lightning y lo que pide
# (aiohttp y compañía), que el trabajador no usa para nada más; no toca torch ni numpy. Instalado el 26-10-2026 con
# `pip check` sin roturas; lo que arrastra tiene rueda para Python 3.12 (`pip install --dry-run --python-version 3.12
# --only-binary=:all:`).
